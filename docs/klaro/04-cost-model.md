# klaro — 비용 모델 (Cost Model)

**버전** v1.0.1-dev · **작성일** 2026-07-16 · **상태** 초안

관련 문서: [기술 스택](./00-tech-stack.md) · [기술 설계서](./01-technical-design.md) · [데이터 모델](./02-data-model.md) · [API 스펙](./03-api-spec.md) · [UI/UX](./05-ui-ux-design.md)

> **비용 원칙**: 개발 단계는 **무비용**을 목표로 한다. 유료 클라우드 자원 사용을 보류하고 셀프호스팅 OSS·로컬 실행으로 대체한다.
>
> **개발 단계에서 유일하게 비용이 발생하는 항목은 AWS Bedrock(LLM) 토큰 사용뿐이다.** 그 외(컴퓨트·저장·이메일·결제)는 로컬/OSS/테스트 모드로 ₩0.

## 1. 개발 단계 비용 현황 (요약)

| 항목 | 개발 단계 선택 | 개발 비용 | 근거 |
|------|---------------|-----------|------|
| 부하 워커 | 로컬 K8s(k3s/kind) | **₩0** | 개발 머신/온프레미스 자원 |
| 스캔 워커 (SAST/DAST) | 로컬 컨테이너(Semgrep/ZAP) | **₩0** | OSS, 로컬 실행 |
| 아웃바운드 트래픽 | 로컬 네트워크 | **₩0** | 외부 전송 없음 |
| 메트릭/트레이스/로그 | VictoriaMetrics/Tempo/Loki(셀프) | **₩0** | OSS, 로컬 디스크/MinIO |
| 오브젝트 스토리지 | MinIO(S3 호환, 셀프) | **₩0** | 로컬 실행 |
| 관계형 DB | PostgreSQL(컨테이너) | **₩0** | 로컬 실행 |
| Control Plane / 상시 서비스 | 로컬 실행 | **₩0** | 개발 머신 자원 |
| 이메일/알림 | **MailHog** (로컬 SMTP) | **₩0** | 외부 발송 없음 |
| 결제 | **Stripe 테스트 모드** | **₩0** | 실거래·수수료 없음 |
| **AI 리포트 요약** | **AWS Bedrock (Claude)** | **유료(토큰)** | 유일한 개발 단계 유비용 항목 |

> **결론**: 개발 단계 총비용 ≈ **Bedrock 토큰 사용료**. 이를 예산 상한으로 관리하면 그 외 비용은 발생하지 않는다.

## 2. 유일한 유비용 항목 — AWS Bedrock (LLM)

- **용도**: 리포트 AI 요약([설계서 §2.5](./01-technical-design.md)) — 성능 한계점·병목 엔드포인트를 자연어로 생성.
- **과금**: 입력/출력 **토큰당** 과금(Bedrock의 Claude 모델). 리포트 1건당 수 센트 수준.
- **AWS 계정 범위**: AWS는 **Bedrock 전용**으로만 사용. EKS·RDS·S3·SES 등 다른 관리형 서비스는 사용하지 않음.

**비용 통제 (개발 시 반영)**
| 레버 | 효과 |
|------|------|
| 프롬프트 캐싱 | 반복 입력 토큰 절감 |
| 요약 입력 최소화 | 구조화 JSON만 전달, 원시 로그·메트릭 미전달 |
| 리포트 생성 트리거 제한 | 자동 생성 대신 명시적 요청 시 생성(개발) |
| 토큰 예산 상한 | 월 Bedrock 사용량 상한·알럿 설정 |
| 로컬 모의(mock) 모드 | 개발/테스트 중 실제 Bedrock 호출 없이 고정 응답 사용 → 토큰 ₩0 |

> **권장**: 기능 개발·테스트 단계에서는 **mock 요약 응답**을 기본값으로 두고, Bedrock 실호출은 통합 검증 시에만 켠다. 이렇게 하면 개발 대부분 구간에서 비용이 0에 수렴한다.

## 3. 무비용 대체 구성 상세

### 3.1 컴퓨트·오케스트레이션 (AWS 보류)
- 로컬 K8s(k3s/kind) 또는 Docker Compose로 워커를 구동 → **관리형 K8s·EC2 비용 없음**.
- 워커 즉시 회수(idle=0) 원칙은 유지 → 로컬 자원도 낭비 없이 회수.

### 3.2 저장 (AWS S3/RDS 보류)
- **MinIO**(S3 호환)로 리포트 PDF·로그/트레이스 아카이브 → S3 API 그대로라 **프로덕션 전환 시 코드 변경 최소**.
- PostgreSQL·Redis·VictoriaMetrics는 컨테이너로 로컬 실행.
- 보존 정책([BILL-03])은 동일하게 적용하되, 로컬 디스크 용량만 관리.

### 3.3 이메일/알림 (SES 보류)
- **MailHog**: 앱이 보낸 메일을 로컬에서 가로채 웹 UI로 확인. 외부 발송·건당 비용 없음.
- Slack 등 외부 알림은 개발 단계에 로컬 웹훅 스텁으로 대체.

### 3.4 결제 (Stripe 수수료 보류)
- **Stripe 테스트 모드**로 구독·계량 과금([BILL-01~04]) 흐름 전체를 구현·검증.
- 테스트 모드는 실제 정산·수수료가 없어 **개발 비용 ₩0**.
- 실 수수료는 라이브 전환(실거래) 시에만 발생.

## 4. FinOps 요구사항 (개발 단계)

- **[COST-01] Bedrock 사용량 계량**: 리포트 생성 시 입력/출력 토큰 수 기록 → 유일 비용 항목 추적.
- **[COST-02] Bedrock 예산 알럿**: 월 토큰 사용량 임계치 초과 시 알림.
- **[COST-03] mock 모드 기본화**: 비통합 개발 구간에서 Bedrock 실호출 차단(플래그).
- **[COST-04] 로컬 자원 모니터링**: 컴퓨트·디스크 사용량(로컬)만 관측 — 금전 비용 아님.
- **[COST-05] 유비용 항목 게이트**: Bedrock 외 유료 외부 서비스 호출이 코드에 추가되지 않도록 리뷰 체크리스트로 통제.

## 5. 프로덕션 전환 시 발생하는 비용 (연기됨)

> 아래는 상용 출시 시점에 유비용으로 전환되는 항목. 개발 단계에서는 발생하지 않는다. 승격 매핑은 [기술 스택 §5](./00-tech-stack.md).

| 프로덕션 항목 | 비용 성격 | 개발 단계 대체 |
|---------------|-----------|----------------|
| 관리형 K8s(EKS) + 워커 컴퓨트 | 변동비(VU-Minutes) | 로컬 K8s |
| 아웃바운드 트래픽(부하) | 변동비(GB) | 로컬 네트워크 |
| AWS S3 / RDS·Aurora | 변동/반고정비 | MinIO / 컨테이너 PG |
| 이메일 발송(SES 등) | 변동비(건당) | MailHog |
| Stripe 라이브 | 변동비(매출 %) | Stripe 테스트 |
| 멀티리전 / DR | 고정비 배수 | 단일 로컬 |
| AWS Bedrock | 변동비(토큰) | **개발에서도 동일하게 발생(유일)** |

**단위경제성(프로덕션)**: 판매가(VU-Minutes 단가) > 원가(컴퓨트+트래픽+저장) 유지가 목표. 초과 과금 단가($0.50/1,000 VU-Min)는 프로덕션 원가 확정 후 마진 검증. — 상세 산식은 프로덕션 비용 확정 시 이 문서에 추가.

## 6. 착수 전 확정 필요 (비용 관련)

1. **Bedrock 모델·리전·토큰 예산 상한** 확정.
2. **mock 요약 모드** 구현 우선순위(개발 비용 0 수렴).
3. 로컬 오케스트레이션: Docker Compose vs 로컬 K8s(자원 소요 차이).
4. 프로덕션 원가 산정은 상용 전환 결정 후 별도 진행(현재 연기).
5. **(신규, 2026-08-23) 상시 관측 플랫폼(S3) 과금 모델**: Datadog 유사 목표에 따라 호스트 수·데이터 수집량(GB)·리텐션 기간 기준 과금 축 신설 여부와, 기존 배포 리포트 VU-Minutes 과금과의 병행 방식. 개발 단계는 여전히 셀프호스팅 OSS(₩0)이나, 상시 가동(24/7) 전제이므로 로컬 자원(디스크·메모리) 소요는 잡 기반 대비 커질 수 있어 §4 FinOps 요구사항에 로컬 자원 상한 기준 추가 검토 필요.
