# klaro — UI/UX 설계서 (UI/UX Design)

**버전** v1.0.0-dev · **작성일** 2026-07-16 · **상태** 디자인 리뷰용

관련 문서: [기술 스택](./00-tech-stack.md) · [기술 설계서](./01-technical-design.md) · [데이터 모델](./02-data-model.md) · [API 스펙](./03-api-spec.md) · [비용 모델](./04-cost-model.md)

> 목표: **① 복잡한 설정 없이 URL만으로 테스트를 시작**하고, **② 결과를 한 눈에 이해**할 수 있게 한다. 사용자는 부하/보안/성능 전문가가 아니어도 "지금 배포해도 되는가?"에 즉시 답을 얻어야 한다.

## 1. 디자인 원칙

| 원칙 | 의미 | 화면에서의 실천 |
|------|------|-----------------|
| **한 눈에 (At-a-glance)** | 스크롤·클릭 없이 핵심 결론 먼저 | 상단에 종합 점수·Pass/Fail·핵심 문장 1줄 |
| **점진적 노출 (Progressive disclosure)** | 기본은 단순, 세부는 펼쳐서 | 간단 모드 기본 / 고급 옵션은 접힘 |
| **결론 → 근거 순서** | 판정 먼저, 데이터는 뒷받침 | "배포 가능" → 그 아래 그래프·수치 |
| **상태를 색으로** | 텍스트보다 색·아이콘이 빠르다 | 성공/경고/위험 3색 일관 적용 |
| **불안 해소** | 초보도 안전하다고 느끼게 | 서킷 브레이커·소유권 검증을 UI에서 명시 |
| **10분 첫 성공** | 가입→첫 리포트까지 최단 | 온보딩 위저드 3스텝 |

**핵심 지표 연결**: 가입 후 첫 테스트 완료율(AHA) 60% ← 온보딩 위저드와 "간단 모드"가 직접 책임.

## 2. 타겟 사용자 & 핵심 시나리오

| 사용자 | 목표 | UX 우선순위 |
|--------|------|-------------|
| **김개발** (1인 백엔드) | URL만 넣고 알아서 부하·결과 시각화 | 최소 입력, 자동 추천값, 큰 결과 시각화 |
| **박팀장** (테크리드) | 배포 전 자동 점수·Pass/Fail 게이트 | 리포트 공유, CI 연동 배지, 팀 대시보드 |

**대표 여정 (Happy Path)**
```
가입 → 프로젝트 생성 → 도메인 등록·검증 → [간단 모드] 부하 테스트 실행
     → 실시간 대시보드 관찰 → 배포 적합성 리포트 확인 → 공유 링크 전달
```

## 3. 정보 구조 (IA) & 내비게이션

```
klaro
├─ 대시보드(홈)          ← 최근 테스트·점수 요약, "새 테스트" CTA
├─ 프로젝트
│   └─ [프로젝트]
│       ├─ 개요          ← 최신 배포 적합성 점수, 추세
│       ├─ 부하 테스트    ← 목록 / 생성 / 실시간 / 결과
│       ├─ 보안 스캔      ← SAST/DAST findings
│       ├─ APM           ← 트레이스·병목·로그(배포 리포트용 스냅샷 뷰, 현재 MVP)
│       ├─ 리포트        ← 발행·공유
│       └─ 설정          ← 사이트(도메인) 검증·API 카탈로그, APM SDK, GitHub 연동
├─ 사용량/과금
└─ 조직 설정            ← 멤버·역할·API 키
```

> **2026-08-23**: S3(APM)가 독립 상시 관측 제품(Datadog 유사, 최종 목표)으로 승격됨에 따라, 위 IA의 "프로젝트 > APM"은 배포 리포트가 소비하는 스냅샷 뷰로 남고, 상시 관측(Explorer·알림·대시보드)은 **프로젝트 하위가 아닌 최상위 내비게이션 항목**으로 별도 구성될 가능성이 높다. 화면 설계는 아키텍처 설계(수집 인증 단위·조회 API) 확정 후 진행하며, 범위는 §11에 정리.

**전역 내비게이션**: 좌측 사이드바(프로젝트 스위처 상단 고정) + 상단바(조직·알림·계정). 실행 중 테스트가 있으면 상단바에 **라이브 인디케이터**(맥동 점 + "1개 실행 중") 표시 → 클릭 시 실시간 대시보드로 이동.

## 4. 핵심 화면 설계

### 4.1 온보딩 위저드 (첫 성공까지 3스텝)

목표: 가입 직후 이탈 없이 첫 리포트 도달.

```
 ① 대상 입력            ② 도메인 검증           ③ 실행 & 관찰
┌────────────────┐   ┌────────────────────┐   ┌────────────────┐
│ 테스트할 URL?   │   │ 소유권 확인 필요     │   │  ▶ 부하 시작    │
│ [https://...  ]│──▶│ 아래 중 택1:        │──▶│  실시간 그래프  │
│                │   │ ◉ DNS TXT 복사      │   │  움직이는 결과  │
│ 자동 추천:      │   │ ○ challenge.txt     │   │                │
│ VU 50·1분(무료)│   │ [검증하기] ⏳→✅     │   │  10분 내 리포트 │
└────────────────┘   └────────────────────┘   └────────────────┘
```

UX 포인트
- URL 입력 즉시 **추천 시나리오 자동 채움**(플랜 한도 내 VU·기간). 사용자는 그대로 "시작"만 눌러도 됨.
- 도메인 검증은 **복사 버튼 + 상태 뱃지**(대기→검증중→완료)로 실패 지점을 즉시 표시. DDoS 악용 방지 게이트([SC-01])를 "당신의 서버만 테스트할 수 있게 확인합니다"로 안심 문구화.
- 3스텝 진행바 상시 표시, 각 스텝 예상 소요시간 안내.

### 4.2 부하 테스트 생성 — 간단/고급 2단 구성

```
┌─ 새 부하 테스트 ─────────────────────────────────────┐
│ 대상 사이트 [ staging.example.com  ▼검증됨 ]         │
│                                                      │
│ 테스트할 API (카탈로그에서 선택 · 트래픽 가중치)      │
│  ☑ GET  /api/v1/products   [======●=] 60%           │
│  ☑ POST /api/v1/login      [===●====] 30%           │
│  ☑ GET  /api/v1/health     [●=══════] 10%           │
│  ＋ API 추가 · 카탈로그 관리                          │
│                                                      │
│ ◉ 간단 모드                                          │
│   동시 사용자 [====●══════] 1,000 VU (가중치로 분배) │
│   지속 시간   [══●════════] 5분                       │
│   예상 사용량: 5,000 VU-Minutes (Pro 한도 내)        │
│                                                      │
│ ▸ 고급 모드 (펼치기)                                  │
│    · 램프업 곡선 · API별 임계치 · 순차 여정(journey)   │
│    · 시나리오 레코더로 가져오기(Chrome 확장)          │
│                                                      │
│ 🛡 안전장치: 대상 에러율 80% 초과 시 자동 중단        │
│                            [ 취소 ]   [ ▶ 테스트 시작 ]│
└──────────────────────────────────────────────────────┘
```

UX 포인트
- **사이트 선택 → API 다중 선택**: 검증된 사이트를 고르면 등록된 API 카탈로그가 뜨고, 여러 API를 체크해 한 번에 테스트([CAT-01], [LG-04]).
- **가중치 슬라이더**: API별 트래픽 비중(합계 100%)을 조절 → 총 VU를 비율로 분배. 실제 운영 트래픽 믹스를 재현.
- 카탈로그가 비었으면 인라인으로 "API 추가"(메서드·경로) 유도, "카탈로그 관리"로 사이트 설정 이동.
- **슬라이더 + 실시간 사용량/비용 미리보기**: 한도 초과 시 즉시 경고와 초과 과금 안내([BILL-02]).
- 고급 옵션은 접힘 상태가 기본(점진적 노출). 순차 여정(journey) 모드는 고급에서 선택.
- 서킷 브레이커를 **눈에 보이는 안전 약속**으로 배치 → 초보의 "내 서버 죽으면 어쩌지" 불안 해소.

### 4.3 실시간 테스트 대시보드 (핵심 화면)

부하가 도는 동안 "무슨 일이 일어나는지"를 라이브로. 갱신 ≤2초([APM-02]).

```
┌ 부하 테스트 · 실행 중 ● LIVE ─────────────  경과 03:12 / 05:00 ┐
│                                                                │
│  현재 VU        RPS         P95 지연        에러율             │
│  ┌────────┐   ┌────────┐   ┌────────┐    ┌────────┐          │
│  │  1,000 │   │ 4,210  │   │1.85s ▲ │    │ 2.0% ● │          │
│  └────────┘   └────────┘   └ 경고    ┘    └ 정상   ┘          │
│                                                                │
│  지연 시간 추세 (P50/P95/P99)          VU 램프                 │
│  ┌──────────────────────────┐   ┌──────────────────────┐     │
│  │      ╱╲    ╱P99           │   │        ▁▂▃▄▅▆▇█       │     │
│  │  ╱╲╱  ╲╱╲╱  P95           │   │   VU 증가 곡선        │     │
│  │ ────────── P50            │   └──────────────────────┘     │
│  └──────────────────────────┘                                │
│  🛡 서킷 브레이커: 정상 (에러율 임계 80%)   [ ■ 중지 ]         │
└────────────────────────────────────────────────────────────┘
```

UX 포인트
- **KPI 타일 4개**(VU·RPS·P95·에러율)를 최상단에, 각 타일에 상태색·추세 화살표(▲▼).
- 라인차트는 임계선(threshold)을 점선으로 겹쳐 표시 → 넘는 순간 색 전환.
- 서킷 브레이커 발동 시: 상단 배너 전환 + 토스트 알림 + "안전하게 중단했습니다" 설명(사고가 아니라 보호임을 강조).
- 스트림 끊김([EDGE-02]) 시: 그래프를 회색 처리 + "대상 서버 응답 없음 — 확인 중" 상태.

### 4.4 배포 적합성 리포트 (한 눈 결론)

가장 중요한 화면. **결론을 먼저, 근거는 아래로.**

```
┌ 배포 적합성 리포트 · staging.example.com ────────────────────┐
│                                                              │
│        ┌─────────────┐        판정                           │
│        │    78 / 100 │        ⚠ 조건부 배포 가능             │
│        │   ◕ 게이지   │        "동시접속 1,250명부터 응답     │
│        └─────────────┘         2초 초과. 결제 API 병목."      │
│                                                              │
│   성능 82 ●     보안 74 ⚠     안정성 80 ●                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ 성능 한계점                                            │  │
│  │  ▸ 안전 동시접속: ~1,250 VU                            │  │
│  │  ▸ 병목: POST /api/v1/payment (DB 커넥션 부족)         │  │
│  │  ▸ [트레이스 보기 →]                                   │  │
│  ├──────────────────────────────────────────────────────┤  │
│  │ 보안 (심각도별)   🔴2  🟠5  🟡8  ⚪3   [상세 →]        │  │
│  └──────────────────────────────────────────────────────┘  │
│  [ PDF 다운로드 ]  [ 🔗 공유 링크 생성 ]                     │
└──────────────────────────────────────────────────────────┘
```

UX 포인트
- **종합 점수 게이지 + 3단 판정**(🟢 배포 가능 / ⚠ 조건부 / 🔴 위험)을 가장 크게.
- **AI 요약 한 문장**([RP-02])을 판정 옆에 배치 → 비전문가도 즉시 이해.
- 성능/보안/안정성 서브스코어를 색 배지로 → 어디가 문제인지 스캔 가능.
- 공유 링크는 비밀번호·만료 옵션 모달([RP-04]), 투자사·이해관계자 전달용.

### 4.5 보안 findings 뷰

```
┌ 보안 스캔 결과 ─────────────────────────────────────────┐
│ 필터: [전체] [🔴Critical] [🟠High] ... [무시된 항목 포함]│
│                                                          │
│ 🔴 SQL Injection  · api/users.js:42   [SAST]            │
│    ▸ 근거 코드 · 권장 수정 · [무시하기]                  │
│ 🟠 하드코딩된 API Key · config.py:8    [SAST]           │
│ 🟡 취약 의존성 lodash@4.17.4           [Dependency]     │
└──────────────────────────────────────────────────────┘
```

UX 포인트
- 심각도 색상으로 정렬·필터. 각 항목 펼치면 코드 스니펫 + 권장 수정.
- **오탐 관리([SC-04])**: "무시하기" → 사유 입력 모달 → 목록에서 회색 처리(재스캔에도 유지).

### 4.6 APM 병목 트레이스

- 응답 ≥3초 트랜잭션([APM-03])을 **워터폴(span) 뷰**로 표시: 어떤 DB 쿼리/함수가 오래 걸렸는지 막대 길이로 즉시 파악.
- 부하 그래프와 **시간축 동기화** → "지연 급증 구간"을 클릭하면 해당 시각 트레이스로 이동.

## 5. 데이터 시각화 가이드

**색상 시맨틱 (전 화면 일관 — 색만으로 판단 금지, 아이콘·라벨 병기)**

| 의미 | 색 | 아이콘 | 사용처 |
|------|-----|--------|--------|
| 정상 / 통과 | 초록 | ● / ✓ | 판정, 에러율 정상, Pass |
| 경고 / 주의 | 앰버 | ⚠ | 임계 근접, 조건부 배포 |
| 위험 / 실패 | 레드 | ✕ / 🔴 | 임계 초과, Critical, Fail |
| 중립 / 정보 | 그레이 | ○ | 미측정, 비활성, 무시됨 |

**차트 유형 선택**
| 데이터 | 차트 | 이유 |
|--------|------|------|
| 지연 시간 추세 | 다중 라인(P50/95/99) + 임계선 | 시간에 따른 분포·초과 시점 |
| VU 램프 | 에어리어 | 부하 증가 시각화 |
| 처리량(RPS) | 라인 | 추세 |
| 응답 코드 분포 | 스택 바 | 2xx/4xx/5xx 비율 |
| 보안 심각도 | 세그먼트 카운트 배지 | 개수 빠른 스캔 |
| 트레이스 | 워터폴(span) | 구간별 소요 |
| 종합 점수 | 방사형 게이지 | 단일 값 강조 |

**원칙**: 축 라벨·단위 항상 표기, 실시간 그래프는 슬라이딩 윈도우, 데이터 없을 때는 빈 상태 안내(0으로 오해 금지), 다크/라이트 테마 모두 대비 4.5:1 이상.

## 6. 디자인 시스템 (토큰)

- **컬러**: Primary(브랜드) 1색 + 상태 3색(초록/앰버/레드) + 그레이 스케일. 라이트·다크 테마 토큰 쌍으로 정의.
- **타이포**: 숫자 강조용 등폭/tabular 숫자 폰트(대시보드 수치 정렬). 본문 Sans. 스케일 예: 32/24/20/16/14/12.
- **간격**: 4px 베이스 스페이싱(4·8·12·16·24·32).
- **그리드**: 12컬럼, 최대 폭 1280px, 사이드바 고정.
- **컴포넌트**: KPI 타일, 상태 배지, 게이지, 라인/에어리어 차트, 진행바, 슬라이더, 필터 칩, 토스트, 모달, 빈/로딩/에러 상태 카드, 라이브 인디케이터.

## 7. 상태 디자인 (Empty / Loading / Streaming / Error)

| 상태 | 처리 |
|------|------|

## 8. 반응형 & 접근성

- **반응형**: 데스크톱 우선(대시보드), 태블릿 2열→1열, 모바일은 조회/알림 중심(테스트 생성은 데스크톱 권장). 차트는 가로 스크롤 컨테이너로 오버플로 처리.
- **접근성(WCAG 2.2 AA)**: 색+아이콘+라벨 병기(색맹 대응), 대비 4.5:1, 키보드 내비게이션, 실시간 값 변경 `aria-live`, 포커스 링, 차트 대체 텍스트/데이터 테이블 토글.
- **국제화**: 한국어 기본, 문자열 외부화(향후 영어). 숫자·시간 로케일 포맷.

## 9. 마이크로카피 & 알림 톤

- **톤**: 간결·안심·행동 유도. 전문용어는 괄호 설명.
- 예) 서킷 브레이커: "대상 서버를 보호하기 위해 테스트를 안전하게 중단했어요." / 도메인 검증: "본인 소유 서버만 테스트할 수 있도록 확인하는 단계예요."
- **알림 채널**: 인앱 토스트(즉시), 이메일(개발=MailHog로 확인), 완료·중단·임계 초과 이벤트에 발송.

## 10. 개발 핸드오프 노트

- 부하 테스트 생성은 **사이트(domain) + API 카탈로그 다중 선택 + 가중치**로 구성([API 스펙 §3.2·§3.6](./03-api-spec.md)): 요청 바디 `domain_id` + `scenario.apis[{endpoint_id, weight}]`. API 카탈로그 CRUD는 [`/projects/:id/domains/:domainId/endpoints`](./03-api-spec.md).
- 결과·리포트는 **API별 분해**를 표시: `/load-tests/:id/results`의 `per_api[]`(API별 rps·p95·error_rate)와 `bottleneck_endpoint`로 병목 API 강조([데이터 모델 §2.3 load_test_results](./02-data-model.md)).
- 실시간 대시보드는 **WebSocket 구독**([API 스펙 §3.2 `/load-tests/:id/stream`](./03-api-spec.md))에 바인딩 — 값 스키마: `rps·latency_p95_ms·error_rate·active_vu`.
- 리포트 화면은 [`/reports/:id`](./03-api-spec.md) 응답의 `performance_score·security_score·ai_summary`에 매핑.
- 보안 findings 필터/무시는 [`PATCH /scans/:id/findings/:id`](./03-api-spec.md)와 `finding_hash` 기준 상태 유지([데이터 모델 §2.4](./02-data-model.md)).
- 사용량 슬라이더 미리보기는 [`/orgs/:orgId/usage`](./03-api-spec.md)·플랜 한도로 계산.
- 차트 라이브러리: **Recharts/visx**([기술 스택](./00-tech-stack.md)). 색 토큰은 §5·§6 기준으로 테마 변수화. *(2026-08-24: `apps/observability-dashboard`는 고밀도 시계열을 캔버스로 그리는 **uPlot**으로 전환, 커스텀 시각화는 **visx/d3** 유지 — 상시 관측 대시보드 P1 파운데이션.)*
