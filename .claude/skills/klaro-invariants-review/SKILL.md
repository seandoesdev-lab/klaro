# klaro-invariants-review — 불변식·비용 감사

klaro의 타협 불가 규칙을 코드 근거로 감사하는 최종 게이트. 통과 없이는 "완료"가 아니다.

## 감사 항목 (각 항목: 통과/위반 + 파일:라인 근거)

1. **RLS 멀티테넌시** — `org_id` 스코프 테이블에 RLS 정책이 있고, 요청 경로가 `SET app.current_org`를 강제하는가? 애플리케이션 필터만으로 대체한 우회 쿼리가 없는가?
2. **도메인 소유권 게이트([SC-01])** — 부하/DAST 잡 생성 경로가 `verified_domains` 검증을 선행 강제하는가? (미검증 → REJECTED/403)
3. **Ephemeral 소스** — 스캔 소스가 tmpfs(RAM)에서만 처리되고 디스크/DB 기록 경로가 없으며 잡 종료 시 소멸하는가?
4. **전송 보안** — CP↔Worker·APM OTLP가 mTLS인가? 외부는 TLS인가?
5. **잡 안전** — 상태머신 전이 검증 + 서킷 브레이커(에러율>80% abort)가 구현됐는가?
6. **비용 게이트([COST-05])** — Bedrock 외 유료 외부 서비스 호출이 없는가? AI 요약 mock 기본([COST-03])? 스토리지 S3 호환 추상화?
7. **감사 로그** — 잡·과금·권한 변경 이벤트가 기록되는가?

## 방법
- `grep`으로 위험 패턴을 먼저 탐지: 유료 SDK import(예: S3 외 AWS 관리형), 원시 SQL에서 `org_id` 누락, 소스 체크아웃 경로가 tmpfs가 아님, TLS 비활성 옵션.
- 각 위반에 **왜 위험한지**를 붙인다(예: 미검증 도메인 부하 = DDoS 악용 통로). 강압적 지시가 아니라 이유로 설득한다.

## 산출물
`_workspace/06_invariants-reviewer_verdict.md` — 항목별 판정 + 종합 판정(**배포 가능 / 조건부 / 차단**). critical 위반이 하나라도 있으면 "차단".

## 원칙
자기 승인 금지 — 빌더가 만든 코드만 검토하고 직접 고치지 않는다. 위반은 해당 빌더에게 수정 요청으로 넘긴다.
