# klaro-integration-qa — 통합 정합성 검증

핵심은 "파일이 존재하는가"가 아니라 **"경계면이 맞는가"**다. 통합 버그는 대부분 서비스 경계에서 shape이 어긋날 때 발생한다.

## 절차 (증분 — 모듈 완성 직후 즉시)

### 1. 경계면 교차 비교
백엔드 API 응답과 프론트 훅/타입을 **동시에 열어** 대조한다:
- 필드명·타입·nullable·중첩 구조 일치 여부.
- 중점: 부하 결과 `per_api[]`(각 항목 필드), 실시간 스트림 필드, 페이지네이션 `{data,next_cursor}`, 에러 `{error:{code,message}}`.
- 불일치 발견 시 양쪽 파일:라인을 근거로 결함 기록.

### 2. 불변식 런타임 검증 (실제 실행)
- **RLS**: org A 컨텍스트로 org B 데이터 SELECT → 0행이어야 함. `SET app.current_org` 미설정 시 접근 차단 확인.
- **도메인 게이트**: 미검증 도메인으로 부하 생성 → `403 DOMAIN_NOT_VERIFIED`. endpoint가 domain 비소속 → `422`.
- **잡 상태머신**: 불법 전이(예: `COMPLETED→RUNNING`) 거부 확인.
- **서킷 브레이커**: 에러율>80% 주입 → `ABORTED` + 부분 결과 보존.
- **Ephemeral**: 스캔 잡 종료 후 소스 파일이 디스크에 남지 않음.

### 3. 결함 보고
`_workspace/05_qa-verifier_report.md`에 결함별로: 요약 · 재현 절차 · 경계면 위치(양쪽 파일:라인) · 심각도(critical/high/medium) · 상태. 결함은 은폐·삭제하지 않는다.

## 환경 제약
검증 스크립트 실행 불가 시(DB/워커 미기동) 그 사실을 보고서에 명시하고 정적 대조(코드 읽기)로 대체하되, "런타임 미검증"으로 표시한다.

## 왜 이렇게 하나
klaro는 CP·워커·프론트·시계열 저장소가 각기 다른 언어/프로토콜로 통신한다. "각 모듈은 동작하는데 합치면 깨지는" 경계면 버그가 구조적으로 잦으므로, 통합 후 1회가 아니라 모듈마다 즉시 교차 검증해야 조기에 잡힌다.
